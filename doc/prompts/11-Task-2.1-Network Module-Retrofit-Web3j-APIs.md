### 3. Moshi Custom Adapters

Create Moshi adapters for types that need special serialization.

```kotlin
package com.nexvault.wallet.core.network.adapter

import com.squareup.moshi.FromJson
import com.squareup.moshi.JsonDataException
import com.squareup.moshi.ToJson
import java.math.BigDecimal
import java.math.BigInteger

/**
 * Moshi adapter for BigDecimal values.
 *
 * JSON numbers and strings are both accepted as input.
 * Output is always a string to prevent precision loss.
 *
 * Ref: doc/07-TEST-CASES.md TC-NET-001 — must parse "123456789.123456789"
 * without precision loss.
 */
class BigDecimalAdapter {
    @FromJson
    fun fromJson(value: String): BigDecimal {
        return try {
            BigDecimal(value)
        } catch (e: NumberFormatException) {
            throw JsonDataException("Invalid BigDecimal: $value")
        }
    }

    @ToJson
    fun toJson(value: BigDecimal): String {
        return value.toPlainString()
    }
}

/**
 * Moshi adapter for BigInteger values.
 *
 * Used for gas prices, nonces, and other large integer values from
 * blockchain RPCs and explorer APIs.
 */
class BigIntegerAdapter {
    @FromJson
    fun fromJson(value: String): BigInteger {
        return try {
            // Handle hex strings (0x prefix) common in Ethereum
            if (value.startsWith("0x") || value.startsWith("0X")) {
                BigInteger(value.removePrefix("0x").removePrefix("0X"), 16)
            } else {
                BigInteger(value)
            }
        } catch (e: NumberFormatException) {
            throw JsonDataException("Invalid BigInteger: $value")
        }
    }

    @ToJson
    fun toJson(value: BigInteger): String {
        return value.toString()
    }
}

/**
 * Moshi adapter that validates Ethereum addresses.
 *
 * Ref: doc/07-TEST-CASES.md TC-NET-002, TC-NET-003
 * - Valid: "0x" + 40 hex chars = 42 chars total
 * - Invalid: missing 0x prefix, wrong length
 *
 * NOTE: This adapter is for VALIDATION during deserialization.
 * It stores the address as a plain String.
 * If you want a dedicated Address type, create a value class instead.
 */
class EthereumAddressAdapter {
    @FromJson
    fun fromJson(value: String): String {
        val trimmed = value.trim()
        if (!isValidAddress(trimmed)) {
            throw JsonDataException(
                "Invalid Ethereum address: '$trimmed'. " +
                "Expected 42 characters with 0x prefix."
            )
        }
        return trimmed
    }

    @ToJson
    fun toJson(value: String): String = value

    companion object {
        private val ADDRESS_REGEX = Regex("^0x[0-9a-fA-F]{40}$")

        fun isValidAddress(address: String): Boolean {
            return ADDRESS_REGEX.matches(address)
        }
    }
}
```

**CRITICAL INSTRUCTIONS FOR THE AI:**
1. The `EthereumAddressAdapter` is a bit tricky with Moshi. Since both input and output
   are `String`, Moshi might have trouble distinguishing when to apply it. There are
   two approaches:
   - **Approach A (simpler):** Don't register it as a global Moshi adapter. Instead,
     use it as a utility validation function called manually when parsing responses.
   - **Approach B (type-safe):** Create a `@JvmInline value class EthAddress(val hex: String)`
     and write the adapter for that type. Then use `EthAddress` in DTOs where addresses appear.
   
   **Use Approach A** for simplicity — register `BigDecimalAdapter` and `BigIntegerAdapter`
   with Moshi, but keep `EthereumAddressAdapter` as a validation utility class only
   (don't add it to the Moshi builder). We'll call its `isValidAddress()` method directly.

2. For `BigDecimalAdapter` — Moshi may also receive JSON numbers (not strings). You may
   need `@FromJson fun fromJsonNumber(value: Double): BigDecimal` as an overload, or
   use `@FromJson fun fromJson(reader: JsonReader): BigDecimal` to handle both cases.
   The safest approach:
   ```kotlin
   @FromJson
   fun fromJson(reader: JsonReader): BigDecimal {
       return when (reader.peek()) {
           JsonReader.Token.NUMBER -> BigDecimal(reader.nextDouble().toString())
           JsonReader.Token.STRING -> BigDecimal(reader.nextString())
           else -> throw JsonDataException("Expected number or string for BigDecimal")
       }
   }
   ```
   This handles both `"1.5"` (string) and `1.5` (number) from JSON. Use this approach.

3. Similarly for `BigIntegerAdapter`, handle both JSON strings and numbers.

### 5. Retrofit API Service Interfaces

```kotlin
package com.nexvault.wallet.core.network.api

import com.nexvault.wallet.core.network.dto.*
import retrofit2.http.GET
import retrofit2.http.Path
import retrofit2.http.Query

/**
 * CoinGecko API service for cryptocurrency prices and market data.
 *
 * Base URL: https://api.coingecko.com/api/v3/
 *
 * Free tier rate limit: ~10-30 requests/minute.
 * Ref: doc/05-IMPLEMENTATION-PLAN-PHASE2.md Task 2.1.3
 */
interface CoinGeckoApi {

    /**
     * Fetches current prices for multiple tokens in the specified currency.
     *
     * @param ids Comma-separated CoinGecko coin IDs (e.g., "ethereum,uniswap,usd-coin")
     * @param vsCurrencies Target currency (e.g., "usd")
     * @param include24hChange Whether to include 24h price change percentage
     * @return Map of coin ID to price data
     *
     * Example: getTokenPrices("ethereum,uniswap", "usd", true)
     * Response: {"ethereum": {"usd": 1650.42, "usd_24h_change": 2.34}, ...}
     */
    @GET("simple/price")
    suspend fun getTokenPrices(
        @Query("ids") ids: String,
        @Query("vs_currencies") vsCurrencies: String = "usd",
        @Query("include_24hr_change") include24hChange: Boolean = true,
    ): Map<String, TokenPriceResponse>

    /**
     * Fetches historical price data for charting.
     *
     * @param coinId CoinGecko coin ID (e.g., "ethereum")
     * @param vsCurrency Target currency (e.g., "usd")
     * @param days Number of days (1, 7, 30, 90, 365, "max")
     * @return Price history with timestamp-value pairs
     */
    @GET("coins/{id}/market_chart")
    suspend fun getPriceHistory(
        @Path("id") coinId: String,
        @Query("vs_currency") vsCurrency: String = "usd",
        @Query("days") days: String,
    ): PriceHistoryResponse
}

/**
 * Etherscan-compatible block explorer API service.

 * This interface works with Etherscan, BscScan, and PolygonScan since they all

     * @param sort Sort order ("asc" or "desc")

    @GET("api")
    suspend fun getTransactions(
        @Query("module") module: String = "account",
        @Query("action") action: String = "txlist",
        @Query("address") address: String,
        @Query("startblock") startBlock: Long = 0,
        @Query("endblock") endBlock: Long = 99999999,

        @Query("offset") offset: Int = 20,
        @Query("sort") sort: String = "desc",

     * Fetches ERC-20 token transfer events for an address.
     */
    @GET("api")
    suspend fun getTokenTransfers(
        @Query("module") module: String = "account",
        @Query("action") action: String = "tokentx",
        @Query("address") address: String,
        @Query("startblock") startBlock: Long = 0,
        @Query("endblock") endBlock: Long = 99999999,
        @Query("page") page: Int = 1,
        @Query("offset") offset: Int = 20,

```kotlin
package com.nexvault.wallet.core.network.web3

 *
 * Web3j instances are expensive to create (they set up HTTP connections).
 * This class reuses them via a ConcurrentHashMap keyed by chain ID.
 *
 * Ref: doc/09-PERFORMANCE-OPTIMIZATION.md Section 5.2 — Web3j Instance Caching
 * Ref: doc/05-IMPLEMENTATION-PLAN-PHASE2.md Task 2.1.4
 *
 * Usage:
 * ```
 * val web3j = web3jProvider.getWeb3j(chainId = 1)
 * val blockNumber = web3j.ethBlockNumber().send().blockNumber
 * ```
 */
@Singleton
class Web3jProvider @Inject constructor(
    private val chainConfigProvider: ChainConfigProvider,
) {
    private val instances = ConcurrentHashMap<Int, Web3j>()

    /**
     * Returns a cached Web3j instance for the given chain ID.
     * Creates a new one if none exists.
     *
     * @param chainId The chain ID (1 for Ethereum mainnet, etc.)
     * @return Web3j instance connected to the chain's RPC URL
     * @throws IllegalArgumentException if the chain ID is not supported
     */
    fun getWeb3j(chainId: Int): Web3j {
        return instances.getOrPut(chainId) {
            val config = chainConfigProvider.getConfig(chainId)
                ?: throw IllegalArgumentException("Unsupported chain ID: $chainId")
            Web3j.build(HttpService(config.rpcUrl))
        }
    }

    /**
     * Shuts down and removes the Web3j instance for a given chain.
     * Call this when a chain is deselected for a long time to free resources.
     */
    fun shutdown(chainId: Int) {
        instances.remove(chainId)?.shutdown()
    }

    /**
     * Shuts down all cached Web3j instances.
     * Call this when the app is being destroyed.
     */
    fun shutdownAll() {
        instances.values.forEach { it.shutdown() }
        instances.clear()
    }
}
```

### 7. Block Explorer API Factory

Since each chain has a different block explorer base URL, we need a factory.

```kotlin
package com.nexvault.wallet.core.network.api

import com.nexvault.wallet.core.network.config.ChainConfigProvider
import com.squareup.moshi.Moshi
import okhttp3.OkHttpClient
import retrofit2.Retrofit
import retrofit2.converter.moshi.MoshiConverterFactory
import java.util.concurrent.ConcurrentHashMap
import javax.inject.Inject
import javax.inject.Singleton

/**
 * Factory that creates and caches BlockExplorerApi Retrofit instances
 * per chain, since each chain has a different explorer base URL.
 *
 * Example:
 * ```
 * val api = blockExplorerApiFactory.getApi(chainId = 1)
 * val txs = api.getTransactions(address = "0x...", apiKey = "...")
 * ```
 */
@Singleton
class BlockExplorerApiFactory @Inject constructor(
    private val okHttpClient: OkHttpClient,
    private val moshi: Moshi,
    private val chainConfigProvider: ChainConfigProvider,
) {
    private val cache = ConcurrentHashMap<Int, BlockExplorerApi>()

    /**
     * Returns a BlockExplorerApi instance for the given chain.
     * Caches instances to avoid recreating Retrofit for the same chain.
     *
     * @param chainId The chain ID
     * @return BlockExplorerApi configured for that chain's explorer
     * @throws IllegalArgumentException if chain is not supported
     */
    fun getApi(chainId: Int): BlockExplorerApi {
        return cache.getOrPut(chainId) {
            val config = chainConfigProvider.getConfig(chainId)
                ?: throw IllegalArgumentException("Unsupported chain ID: $chainId")

            Retrofit.Builder()
                .baseUrl(config.explorerApiBaseUrl)
                .client(okHttpClient)
                .addConverterFactory(MoshiConverterFactory.create(moshi))
                .build()
                .create(BlockExplorerApi::class.java)
        }
    }

    /**
     * Convenience method that returns the explorer API key for a chain.
     * Call this alongside getApi() when making requests that need the key.
     */
    fun getApiKey(chainId: Int): String {
        return chainConfigProvider.getConfig(chainId)?.explorerApiKey ?: ""
    }
}

### 8. OkHttp Interceptors

```kotlin
package com.nexvault.wallet.core.network.interceptor

import okhttp3.Interceptor
import okhttp3.Response

/**
 * Interceptor that adds CoinGecko API key header if available.
 *
 * The free tier of CoinGecko doesn't require a key, but the Pro tier
 * uses the header "x-cg-pro-api-key". We add it only if a key is provided.
 */
class CoinGeckoApiKeyInterceptor(
    private val apiKey: String,
) : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val request = if (apiKey.isNotBlank()) {
            chain.request().newBuilder()
                .header("x-cg-demo-api-key", apiKey)
                .build()
        } else {
            chain.request()
        }
        return chain.proceed(request)
    }
}

/**
 * Interceptor that adds cache control headers for price API responses.
 *
 * Prices don't change every second, so we cache responses for 30 seconds
 * to reduce API calls and improve performance.
 *
 * Ref: doc/09-PERFORMANCE-OPTIMIZATION.md Section 3.2
 */
class CacheControlInterceptor : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val response = chain.proceed(chain.request())
        return response.newBuilder()
            .header("Cache-Control", "public, max-age=30")
            .build()
    }
}

/**
 * Utility for validating Ethereum addresses.
 *
 * Ref: doc/07-TEST-CASES.md TC-NET-002, TC-NET-003

object AddressValidator {
    private val ADDRESS_REGEX = Regex("^0x[0-9a-fA-F]{40}$")

    /**
     * Validates that the given string is a valid Ethereum address.
     *
     * A valid address is:
     * - 42 characters long
     * - Starts with "0x"
     * - Followed by 40 hex characters (0-9, a-f, A-F)
     *
     * This does NOT validate EIP-55 checksum casing.
     */
    fun isValid(address: String): Boolean {
        return ADDRESS_REGEX.matches(address.trim())
    }

### 13. Common Issues to Watch For:

**Issue: Moshi generic type adapter**
Do NOT use `EtherscanResponse<T>` with Moshi codegen. It won't work. Use concrete types
like `EtherscanTransactionListResponse` with the result type directly embedded.

**Issue: Web3j dependency conflicts**
Web3j pulls in many transitive dependencies (Bouncy Castle, etc.) that may conflict with
other libraries. If you get dependency resolution errors, add to `core-network/build.gradle.kts`:
```kotlin
configurations.all {
    resolutionStrategy {
        force("org.bouncycastle:bcprov-jdk15on:1.70")
    }
}
```
Or use `exclude` on specific transitive deps. This is a common issue — warn the user
if it might happen.

**Issue: OkHttp cache not working**
The cache only works with GET requests that have proper `Cache-Control` response headers.
CoinGecko's API does return cache headers, but our `CacheControlInterceptor` overrides
them. This is intentional — we want a 30-second cache for price data.

**Issue: BuildConfig not generating**
If `BuildConfig.INFURA_API_KEY` doesn't resolve, ensure:
1. `buildFeatures { buildConfig = true }` is in the `android` block
2. The `buildConfigField` calls are in `defaultConfig`
3. Sync Gradle after adding them

**Issue: Multiple OkHttpClient instances**
We provide ONE base OkHttpClient and use `.newBuilder()` to create per-API variants
(e.g., with the CoinGecko API key interceptor). This shares the connection pool and
thread pool, which is efficient. Do NOT create separate `OkHttpClient.Builder()` calls
from scratch for each API.

**Issue: BigDecimalAdapter receiving JSON number vs string**
CoinGecko returns numbers as JSON numbers (not strings): `"usd": 1650.42`.
Etherscan returns numbers as strings: `"value": "1000000000000000000"`.
The BigDecimalAdapter must handle BOTH formats. Use the `JsonReader` approach shown
in step 3's instructions.

**Issue: Retrofit base URL must end with /**
Ensure all base URLs end with a `/`:
- `"https://api.coingecko.com/api/v3/"` ✓
- `"https://api.etherscan.io/"` ✓
- `"https://api.coingecko.com/api/v3"` ✗ (missing trailing slash)
